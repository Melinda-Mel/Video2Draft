# 13 - 六平台实战复盘：慢链路的根因与提速（2026-09-20 晚实测定稿）

> 当晚用真实链接把 视频号 / B站 / 小红书 / 抖音 / YouTube / X 六个平台全部端到端实测一遍，
> 边测边修。本文记录每个问题发生的原因、解法，以及最终定型的成功链路，供以后遇到同类问题时直接套用。

## 一、当晚实测成绩单

| 平台 | 首测 | 定型 | 关键瓶颈 |
|---|---|---|---|
| 视频号 | ~40s（首条） | **15.9s** | 编排往返过多 → 合并成一条命令 |
| B站 | 20 分钟+（412 风控） | **20.8s** | 页面风控 → 绕开页面走公开 API |
| 小红书 | 30.2s | 30.2s（正常） | 素材本身大，链路无问题 |

| YouTube | 219.9s | **62.3s** | 下高清全量 → yt-dlp 只下音轨 |
| X | 30.8s（首测即通） | 30.8s | 无 |

## 二、问题 → 原因 → 解法

### 1. B站解析 HTTP 412（当晚最大的坑）
- **现象**：解析服务抓 B站 页面直接 412；换 curl、yt-dlp、带上完整浏览器 cookies 全都 412。
- **根因**：风控看的是 **TLS/HTTP2 指纹**，不是 cookies 和 UA —— 用 Python/Go 客户端伪装浏览器头没用。
- **解法（定型）**：完全不碰 `www.bilibili.com` 页面。
  - `api.bilibili.com/x/web-interface/view?bvid=…` 拿标题/作者/时长/cid；
  - `api.bilibili.com/x/player/playurl?bvid=…&cid=…&fnval=16` 拿媒体流直链；
  - `upos-*.bilivideo.com` 的 m4s/flv 直链，带 `UA + Referer` 就能下；
  - **只下音轨**（dash.audio），体积约 1/4，转写够用。
  - 实现见 `tools/bili_reply.py`。
- **附带坑**：Python `urllib` 默认走环境变量里的代理，B站请求必须直连
  （`ProxyHandler({})`）；`b23.tv` 短链只跟一跳拿 Location，跟到目标站页面就会 412。
- **通用经验**：平台解析失败先试「公开 API + CDN 直链」，别死磕伪装浏览器指纹。

### 2. YouTube 首测 220 秒
- **现象**：一条 1 分钟的 shorts 端到端 219.9s，其中下载占 170s。
- **根因**：通用下载器按**高清全量视频**下载（一条 shorts 就 64.1MB），而机房出口只有
  ~380KB/s；转写只需音频，却把视频整个拖了下来。
- **解法（定型）**：给 make_card 加 YouTube 专用分支
  `tools/yt_reply.py`：`yt-dlp --dump-json` 拿元数据 + 只下 `bestaudio`（64MB → 2.8MB），
  复测同一条视频 **219.9s → 62.3s**。剩余 ~30s 是 yt-dlp 在机房 IP 上解析元数据的固有延迟。
- **附带坑**：首次解析偶发 `EOF`（Go 爬虫瞬断）—— 先用 `curl` 验证域名连通性，
  能通就直接重跑，不要先怀疑环境。
- **通用经验**：**转写只要音轨，能不下视频就不下视频**；链路慢先看素材体积/时长再查代码。

### 3. 小红书 wxcd 适配器必然失败
- **根因**：适配器读的是老版页面结构 `__INITIAL_STATE__.note.noteDetailMap`，
  小红书已改版为 `__INITIAL_STATE__.noteData.data.noteData`。
- **解法（定型）**：`tools/xhs_reply.py` 绕开适配器自己解析页面结构（展开短链 → 抓分享页 →
  解析 noteData → 挑视频流直链下载）。实测 30.2s 全绿。
- **注**：30s 里下载+转写 19.2s 是素材本身决定的（2 分钟视频 8.6MB），链路开销与其它平台一致。
  再想提速可改选低清流（省 3~5s），但会碰转写精度，默认不动。

### 4. 视频号首条 ~40s → 15.9s（编排提速）
- **原因**：「跑转写 → 写 md → 出图 → 推送 → 改 INDEX」五轮独立调用，每轮都有往返延迟。
- **解法（定型）**：打包成一条命令 `make_card.py`，编排开销归零；
  回复格式同时收口为「一段话 + 一张图」。

### 5. 抖音首测即通（15s，最快基准档）
- 分享链一次归一化到 `iesdouyin.com/share/video/<id>`，直出解密好的直链：
  无风控、无二次跳转、无需伪装指纹。全量 mp4 仅 ~1MB（同档小红书视频 8.6MB）。
- **注**：抖音长视频会按「视频时长」规律变慢，属正常，别当故障查。

### 6. X/Twitter
- syndication 接口拿元数据与直链（`tools/x_reply.py`），直链不可得时 yt-dlp 兜底。
  首测 30.8s 即定型。

## 三、定型的耗时基准（2026-09-20 晚四平台+复测定标）

**抖音 ≈15s（最快）→ 视频号 ≈16s → B站 ≈21s → 小红书 ≈31s → X ≈31s → YouTube ≈62s。**

耗时四段固定：下载（正比文件大小）+ 转写（正比音频时长，本地 mlx 引擎 ≈0.1× 实时）
+ LLM 整理 ~4s + 出图+推送 ~7s。**差异几乎全部来自素材本身**：视频越长、文件越大越慢。
遇到慢链路，先看视频时长/大小再下结论，别一上来就查代码。

## 四、反风控通用模板（B站实战定型）

1. 某平台解析失败（尤其 HTTP 412）→ **先试公开 API + CDN 直链**，别死磕伪装浏览器指纹
   （风控看 TLS/HTTP2 指纹，cookies 和 UA 都骗不过）。
2. 转写只需要音轨 → 能下音频流就不下视频流，体积常为 1/4，时间同比。
3. Python `urllib` 默认吃环境变量代理 → 平台请求要直连（`ProxyHandler({})`）。
4. 短链只跟一跳拿 Location，别跟到目标站页面。
5. 出网瞬断（EOF/超时）先 `curl` 探一下域名，能通就直接重跑。
