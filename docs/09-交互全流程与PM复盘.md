## 三、全流程里最关键的点（做对了才活下来的）

1. **形态定在微信里**：不改她的动线——刷视频时顺手转发，不用开电脑、不用复制粘贴到别处。
   这是整个产品最重要的一个决定，其它都是围绕它做的放大器。
2. **交付 = 一句介绍 + 一张长图**：她反复纠正过「别发大段文字」。结果信息密度和阅读成本同时降下来了。
3. **确定性纠错优先于模型纠错**：
   转写已经听错了，靠「提醒模型别改」是纠不回来的 → 必须有本地替换层。
   后来又升级成三层（热词偏置 / 确定性替换 / 提示兜底），现在覆盖 10 个领域 394 条、两层都会真的改。
4. **保守原则**：「宁可漏改，不可乱改」——中文不做模糊匹配、只删明确的复读、句子有一点不同就不动。
   这一条让「自动纠错」这件事从"不可信"变成"可信"。
5. **工作纪律本身是功能**：调度与执行分离、失败两次止损、最小验证（冷 2 热 2 功能 1）、
   时间预算（排错 3 分钟 / 改造 8 分钟）、先实现再记录。纪律换来的是稳定手感。
6. **双形态留存**：md 存真（给 AI 读、可检索），png 好读（给手机读）。她自己想通的这一条，
   比任何一次排版优化都值钱。
7. **只发结果，不发过程**：耗时、字数、瑕疵都不进消息。她要的是"东西"，不是"工作汇报"。

## 四、PM 视角：她的需求其实换了四层

| 层级 | 真实诉求 | 典型原话 | 对应设计 |
|---|---|---|---|
| ① 工具层 | 把长视频变文字 | 「太长了来不及看」 | 转写 + 整理 |
| ② 动线层 | 在我的手机、我的微信里完成，不打断刷视频 | 「我要用手机直接操作」 | 微信渠道接入、一键转发 |
| ③ 质量层 | 转出来能直接用（没错字、能读） | 「李生龙应该是李尚龙吧」「表格要横着划」 | 纠错词表、paper 长图、分段分条 |
| ④ 资产层 | 可留存、可检索、可复用、可被看见 | 「我想把 GitHub 给他」「开源一个新 Skill」 | 归档 + 索引 + 术语库 + 开源打包 |

**给后面的启示**：她现在已经走到第 ④ 层了。以后凡是新功能，先问一句
「这个能不能变成她简历/作品集里的一页？」——不能的，优先级降一级。

## 五、踩过的坑（按性质分类）

**技术类**

- 视频号的链路最脆：本地解析服务、MITM 代理、系统代理、证书、VPN 抢路由……任何一环错都不出结果。
- 平台接口随时会变，**失效是常态**，所以文档里要写「怎么改」，不能只写「怎么用」。
- 转写器在纯音乐/卡点结尾会**复读幻觉**（同一句刷几十遍，还混外语）。
- 专有名词必错（`Jev→GV`、`WorkBuddy→Worker Body`、`CC照长篷→CZ 赵长鹏`）。
- 平台返回的**标题里就带错字**，出图后放大到封面 → 标题也必须过纠错。
- 推送通道 `prepare failed`：**服务端抽风、会自愈**，不是代码问题；文件类型比图片更容易挂。
- 常驻服务（launchd）装不上、收益只有 1 秒 → **砍掉**，不为 1 秒养一套后台。

**产品类**

- 长图太长（最早 4.6 万像素）→ 压缩到 3.6 万，词表导出改成一行一分类。
- MD 在手机端难读 → 双形态（md 留存 / png 阅读）。
- 把"过程信息"（耗时、字数、瑕疵）当结果发出去 → 改成一句介绍 + 一张图。

**流程类**

- 收到链接先去读文档、查状态、解释流程，最后才开跑 → 改成**第一件事就是跑命令**。
- 为「完美方案」持续试错 → 失败两次就止损。
- 旧守护进程在后台重复发稿、测试污染归档 → 停用旧进程、测试前备份。

**沟通类**

- 「要你何用？」（iPad 那次）：她说的是一件事，做的动作是另一件 —— **先复述需求再动手**。
- 一次回一大段 → 她要的是 3 秒回执 + 关键节点汇报。

## 七、对外讲的时候，产品亮点讲这几条

1. **零动线**：在微信里转发一条链接，就长出「要点 + 全文 + 长图」。
2. **本地转写 + 云端整理**：音频不出本机，只有文字上云，隐私与成本都可控。
3. **可维护的纠错词表**：不是靠模型「聪明」，而是一张能长期积累的表——用一次强一次。
4. **一条命令端到端**：把「每完成一步都要重新决策一轮」的成本砍掉。
5. **交付形态适配阅读场景**：md 留存、png 阅读、一句话介绍。
6. **纪律即产品**：止损线、时间预算、最小验证——保证它在真实使用里不崩。

## 八、优化建议（按优先级）

**P0 · 直接影响她每天用**

- **失败必达**：跑不动、卡住、链接不识别，都要在微信里回一句「卡在哪、下一步怎么办」，
  绝不能出现「13 分钟没动静」。这是最伤体验的一类问题。
- **幂等去重**：同一条链接重复发（或转发两次）不重复处理、不重复推送、不重复归档。
- **进度回执**：3 秒内「收到」、30 秒报阶段、2 分钟报卡点（已有纪律，需要固化成机制）。

**P1 · 质量与信任**

- **质量自检报告**：转写完自动列「可疑词 / 疑似人名」，让她一眼扫过。**只提醒不改**。
- **链接形态兼容**：现在只验证过「手机端转发 → 复制链接」一种；补桌面端、分享卡片、短链包装。
- **归档可检索**：补一个本地小索引（谁讲的、什么主题、哪天），把「存下来」变成「找得到」。

**P2 · 往前走一步**

- **选题复用**：把「爆款库」接上——她的真实目的不是看视频，是找能复用的选题（窗口 `…00-42-34` 已经露出苗头）。
- **一键安装包**：install.sh + 配置模板，让别人 clone 下来就能用（见 [07](07-可移植性拆分.md)、[08](08-发布清单与汇总.md)）。
- **能力边界写清楚**：只处理有口播的视频、接口会变、不去水印不爬付费——先降低预期，再交付惊喜。

## 九、一句话结论

**这不是一个「视频转文字」工具，而是一条「刷到 → 转发 → 拿到能用的稿子 → 存起来变成资产」的动线。**
技术上的难处在视频号和多平台解析，产品上的难处在「别打断她、别给她看过程、别给错东西」。
前者已经打通，后者靠纪律和词表在持续变好。
