# 00 · 总览与平台矩阵

## 整体链路

```
        ┌── 用户发链接（微信 / 对话窗口）
        ↓
   ① 平台识别（platforms.py）
        ↓
   ② 解析取直链
        ├─ 通用平台 → 本地解析服务 API
        ├─ 小红书   → 自写解析器（抓分享页 noteData）
        ├─ X        → 公开 syndication 接口（免登录）
        └─ 视频号   → 解析服务 + MITM 代理（微信流量过代理）
        ↓
   ③ 下载 → ④ 提音频（ffmpeg）→ ⑤ 本地转写（mlx-whisper turbo）
        ↓
   ⑥ 专有名词纠错（确定性替换）
        ↓
   ⑦ DeepSeek 整理成「关键要点 + 完整文案」
        ↓
   ⑧ 归档 .md → ⑨ md2pic 出长图 → ⑩ 推送微信 → ⑪ 更新 INDEX
```

全程由 `tools/make_card.py` 一条命令串起来。

## 前置条件（缺了整条链就不成立）

这套东西能跑起来，靠的不只是本机脚本，还有**助理侧的渠道接入**：

1. **助理端要在「管理」里把微信接进来**（连接微信渠道）。
   这是「你发链接 → 助理收到」和「图/说明 → 推回你微信」两个方向的共同前提。
   只装脚本、不接渠道，就只能手动跑命令、自己看输出目录，没有推送这一步。
2. **手机端要有可转发的入口**：目前所有链接都是**手机端点「转发 → 复制链接」得到的那一条**。
   其它形态（桌面端复制、分享卡片、短链服务、别的 App 转出来的链接）**没验证过**，
   不要默认能用。
3. 本机要有：`ffmpeg`、转写引擎、一个模型 API Key、以及（若要做视频号）本地下载器与代理链路。

## 平台支持矩阵（2026-09-20 定稿）

| 平台 | 状态 | 入口 | 备注 |
|---|---|---|---|
| 视频号 | ✅ 已验证 | 解析服务 + MITM 代理 2023 | 用户最常用；需系统代理指向 2023 |
| 抖音 | ✅ 已验证 | 解析服务 | 短链需归一化，否则被出口 reset |
| 小红书 | ✅ 已验证 | 自写 `xhs_reply.py` | 官方适配器结构过期，绕开它 |
| B站 | ✅ 已验证 | 解析服务 | b23.tv 短链可直接识别 |
| YouTube | ✅ 已验证 | 解析服务 | 下载慢（走隧道），转写很快 |
| X / Twitter | ✅ 已验证 | 自写 `x_reply.py` | 公开接口免登录；先确认视频里有人声 |
| 微博 | ❌ 已下线 | — | 用户 2026-09-20 明确去掉 |
| TikTok | ❌ 已下线 | — | 登录不稳定，先放弃 |
| 快手 | ❌ 不做 | — | 用户基本不用 |

识别表仍保留微博 / TikTok 的域名（**只为了认出后回一句说明**），不会进入下载转写。

## 交付形态

固定是「**一张长图 + 一句话**」：

- 长图：封面卡片 + 关键要点徽章 + 分节序号的完整文案，用 `md2pic` 生成
- 一句话：这条讲了什么 + 已推微信 + 存在哪
- 同时把 `.md` 归档到 `~/Documents/资料库/文案素材/`，并登记进 `INDEX.md`

## 目录约定

| 路径 | 作用 |
|---|---|
| `~/WorkBuddy/<时间戳>/` | 每个任务窗口的工作目录（产出物在这里） |
| `~/WorkBuddy/<流水线窗口>/tools/` | 成稿链路的全部脚本 |
| `~/Documents/资料库/文案素材/` | 归档区：每条视频一份 `.md` + 同名 `.png` |
| `~/Documents/资料库/INDEX.md` | 归档总索引（按平台分组） |
| `~/.local/bin/` | 自制 CLI（出图、推送、提醒、检索等） |
| `~/.workbuddy/projects/` | 各窗口的对话记录（jsonl），可跨窗口检索 |
