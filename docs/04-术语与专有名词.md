# 04 · 术语与专有名词

## 为什么要专门管这个

语音转写遇到**产品名、模型名、人名**几乎必错，而且错法有规律
（音近词、拆成两个词、加空格）。这类错误如果只靠「整理阶段提醒模型别改」，
**根本纠不回来**——因为转写阶段已经听错了，整理阶段看到的就是错的东西。

## 三层纠错机制（词表只有一份）

```
① 热词偏置   词表 → 转写器的 initial prompt（解码阶段就倾向正确写法）
② 确定性替换 转写输出 → 逐条正则替换（主力，0 延迟、可复现、可离线）
③ 提示兜底   词表 → 整理阶段的提示词（由同一张表生成，不再手写副本）
```

第 ② 层由 2026-09-20 起扩成**三趟**，两层词表都会真的参与改写（不是只提示）：

| 趟次 | 做什么 | 例子 |
|---|---|---|
| ① 变体表 | 按登记的「误听 → 正确」精确替换（中英文都支持） | 李生龙 → 李尚龙、上裢 → 上链 |
| ② 英文写法归位 | 纯英文词条的大小写 / 空格 / 连字符差异 | `Github` → `GitHub`、`huggingface` → `Hugging Face` |
| ③ 英文拼写近似 | 整词与标准写法相似度 ≥0.85 就归位 | `Kubernets` → `Kubernetes`、`Gitub` → `GitHub` |

**中文故意不做模糊匹配**：同音词太多（「京东」和「惊动」完全同音），硬猜必然误伤正文，
所以中文只走第 ① 趟，确认一处加一条。
另外给 `arm / base / medium / figure / notion / circle / strategy` 这类**本身是常用英文词**的
词条关掉了大小写归位——转英文视频时会把普通单词误改成公司名。

外加 **巡检**：转写完扫一遍「像专有名词但不在词表里」的英文词，
**只提醒、不乱改**，等用户确认后进词表。

替换规则会自动容忍空格 / 点号 / 连字符变体
（同一个名字写成 `AbCd` / `Ab Cd` / `ab-cd` 都能命中）。

## 维护方式

一张表就是唯一维护点，每条包含：

| 字段 | 含义 |
|---|---|
| `name` | 正确写法 |
| `variants` | 见过的误听形态（正则用，两层词表都支持） |
| `aka` | 并列说法 / 简称（只做提示，不会被改写成 `name`） |
| `desc` | 说明，供热词提示与整理提示使用；参考词表导出时已省略以压缩体积 |
| `cat` | 分类，仅用于导出可读清单时分组 |

词表分两层：

- **纠错层**：带 `variants`，听错会被**自动改回**；
- **参考层**：公司 / 创始人 / 模型 / 各行业术语，靠上面的②③趟自动归位，同时作为整理阶段的提示。

当前规模：纠错层 29 条、参考层 362 条，覆盖 10 个领域——
芯片算力、开发工具与开源、创业投融资、产品增长营销、平台内容生态、金融宏观、
美国科技公司人物、中国科技公司人物、区块链 Web3、模型产品。

遇到新听错只加一条变体即可，不用改任何代码。

## 特别注意

- **专有名词一律不是错别字**。看到「音很怪但明显是产品名」的写法，
  先怀疑是转写错误，不要当成用户的错别字去「纠正」。
- 用户自己确认过的写法，要**回填历史归档**（就地修正已存的 `.md`，并重出长图），
  否则旧归档里会一直留着错字。
- 反过来，「原话引用里的脏话/英文」不是错误，**不要动**。

## 人名与专有名词的验收习惯

转写完成后，对「像是人名/产品名但可能听错」的词，**逐个人工核一遍上下文**，
核对方式：

1. 看它在原文里的上下文是否讲得通；
2. 看同一篇里是否出现了两种写法（不一致就是错）；
3. 拿不准就问用户，**不要猜着改**。
