# 01 · 一条链接，一键成稿

一句话：**给一条视频链接，产出一张长图**（关键要点 + 完整文案）**推到微信，同时归档到本地资料库。**

日常只有一条命令：

```bash
python3 tools/make_card.py "<视频链接>"          # 全自动：解析 → 转写 → 整理 → 归档 → 出图 → 推送 → 建索引
python3 tools/make_card.py "<链接>" --no-push    # 只归档出图，不推送
python3 tools/make_card.py "<链接>" --platform 小红书   # 识别失败时手动兜底指定平台
```

结束时打印一行 `@@CARD@@{json}`，含平台、标题、作者、字数、归档路径与分段耗时。

## 输入从哪来、长什么样

- 来源：**手机端点「转发 → 复制链接」得到的那一条**，发到微信对话里。
- 已验证：各平台标准分享链接（含短链域名变体）。
- **未验证**（不要假设可用）：桌面端复制的链接、分享卡片直接转发、第三方短链二次包装、
  别的 App 转出来的链接。
- 链接前后常带平台口令、话题标签、表情等杂质；识别器负责从整段文字里抠 URL，
  所以整条消息**原样发过去就行，不用手动清理**。
- 反过来，推送方向要用户先**在助理的设置里接入微信渠道**（见
  [00-总览与平台矩阵.md](00-总览与平台矩阵.md) 的「前置条件」）。

## 各步骤在做什么

| # | 步骤 | 实现 | 说明 |
|---|---|---|---|
| ① | 平台识别 | `platforms.py` | 正则匹配域名；认不出就报错，不硬猜 |
| ② | 解析取直链 | `pipeline.py` / 平台专用脚本 | 见下方「各平台入口」 |
| ③ | 下载 | 同上 | 落到临时目录，跑完自动清理 |
| ④ | 提音频 | `ffmpeg` | 单声道 16k wav |
| ⑤ | 转写 | `mlx-whisper`（本地） | 默认 `whisper-large-v3-turbo`，中文口播 |
| ⑥ | 专有名词纠错 | `fix_terms.py` | 确定性替换，见 [04-术语与专有名词.md](04-术语与专有名词.md) |
| ⑦ | 结构化整理 | `format_doc.py` → DeepSeek | 产出「关键要点 + 完整文案」 |
| ⑧ | 归档 | `make_card.py` | `资料库/文案素材/<平台>文案-<来源>-YYYYMMDD.md` |
| ⑨ | 出长图 | `~/.local/bin/md2pic` | 自动从 md 元信息行读标题、来源、字数 |
| ⑩ | 推送 | `~/.local/bin/wx-send` | **只发一行说明 + 图** |
| ⑪ | 建索引 | `make_card.py` | 往 `资料库/INDEX.md` 对应平台分组插一行 |

## 各平台入口

| 平台 | 走哪条 | 要点 |
|---|---|---|
| 视频号 | 解析服务 API + MITM 代理 | 唯一需要本地代理的平台；微信客户端流量必须过代理 |
| 抖音 | 解析服务 API | **短链先归一化**成 `iesdouyin.com/share/video/<id>/` |
| 小红书 | `xhs_reply.py` | 自解析分享页，**不走官方适配器**（结构已过期） |
| B站 | 解析服务 API | `b23.tv` 短链可直接用 |
| YouTube | 解析服务 API | 下载慢（走隧道），转写很快 |
| X / Twitter | `x_reply.py` | 公开 syndication 接口，**免登录**；无直链时用 `yt-dlp` 兜底 |

## 交付规范（固定动作）

1. **只发一张图 + 一句话**：说清「这条讲了什么 + 已推微信 + 存在哪」。
   **不报耗时、不报字数、不列瑕疵、不复述全文。**
2. **静默纠错**：只改确定的同音/形近错字，不润色、不改写；
   **绝不外发**「注：xx→yy」这类说明。拿不准的宁可不动。
3. **完整文案要可读**：有结构就按条/分段排，删语气词与改口重复，
   但**一句信息都不能少**，也不改写成书面语。
4. **专有名词必查**：转写完自动巡检「像专有名词但不在词表里」的英文词，
   只提醒不乱改；用户确认后加进词表，下次自动纠。
5. **归档文件名**：`<平台>文案-<来源>-YYYYMMDD.md`，正文首行写
   `**来源**：平台 · 作者 ｜ **归档**：日期 ｜ **字数**：N`。

## 性能账（170 秒视频的实测拆解）

| 环节 | 耗时 | 可优化空间 |
|---|---|---|
| 展开短链 + 抓页面 | ~0.7s | 已很便宜 |
| 下载视频 | 3.6s（国内直连）/ 20~45s（走隧道） | 取决于网络，脚本侧动不了 |
| 提音频 | ~0.5s | 只取音频流与全量下载耗时相同，无收益 |
| **本地转写** | **9~11s** | 占大头，主要是模型加载与解码 |
| 模型整理 | 4~5s | 取决于输出长度 |
| 出图 + 推送 | 5~8s | |
| 进程/写盘开销 | ~4s | |

**已做过的优化与结论**

- ✅ **一条命令端到端**（`make_card.py`）：原本「转写 / 整理 / 归档 / 出图 / 推送」是多轮调用，
  每轮都有往返延迟。打包后只剩一轮。**这是收益最大的一项。**
- ❌ **转写进程常驻**：做过、量过，只净省 ≈1s（模型权重那 3s 被系统文件缓存吃掉大半），
  却要背后台进程 + 自愈拉起 + 异常回退的维护成本。**默认关闭，代码留着，高频批量再启用。**
- ⏳ **收到链接先回一句预计时长**：感知收益比实际提速明显。

## 长图渲染器 `md2pic` 的样式与铁律

样式：顶部渐变色条 → 来源胶囊标签 + 大标题 → h2 蓝底色块横幅 →
「关键要点」渲染成**带序号徽章的卡片** →「完整文案」里 `N. **小标题**` 渲染成**圆形序号分节标题** →
加粗统一主色 → 虚线页脚。

**改这个脚本的两条铁律（都踩过）**

1. **所有 `counter-reset` 一律写在 `.wrap`**，块容器（`.kp` / `.steps` / `ol`）只写 `counter-increment`。
   写在块容器里会被空行拆块、各自从 1 重数，**序号全变成 1**。
2. **不要在 `main()` 里用 `src` 当局部变量名**——它是输入文件路径，被覆盖后输出图会落到当前目录、
   文件名叫成来源名。

改完先做语法检查，再裁顶部/中部/尾部三段做视觉自检。
