# 06 · 发布前检查（脱敏清单）

> 已对当前工作区做过一次扫描。**结论：现在不能原样 push。**
> 下面按「必须处理 / 建议处理 / 明确不要公开」三级列出。

## 零、先决定：分几个仓库

GitHub 上每个仓库可以设成 **公开（public）** 或 **私有（private）**：

- **公开仓**：全世界任何人不登录也能看到全部内容、能 clone。适合放「方法论 + 可复用脚本」。
- **私有仓**：只有你自己（和被邀请的人）能看。适合放「你的全部工作记录」。

**推荐两个仓，而不是一个：**

| | 私有仓（`-private`） | 公开仓（给别人一键用） |
|---|---|---|
| 装什么 | 全部原始记录：协作约定、方案总账、每日记忆、项目档案明细、归档文案、示例产物 | 脱敏后的方法论 + 能跑的核心脚本 + 安装说明 |
| 内容 | 原样 | **重写**，不是复制 |
| 含个人路径 / 账号 / 客户信息 | 可以有（私有，但 Key 依然不进 git） | 一律不许有 |
| 目的 | 自己的备份与回溯 | 让别人能下载、能看懂、能跑起来 |

**判断一句：一份文件里只要有一行是「只有你才需要知道」的信息，它就只进私有仓。**
公开仓从零开始写，需要哪段逻辑就重新表达一遍——比「先复制再删敏感的」安全得多，
因为「删」一定会漏。

## 明确不要公开

- 任何 Key、token、cookie、证书私钥
- 会议记录整理稿、个人使命愿景、个人业务诊断类内容
- 私人设备的网络配置细节（代理端口、隧道规则、内网地址）
- 他人作品的全文转载

## 推送纪律（每次 push 前都走一遍）

1. **先跑自检命令**（见下方）。命中任何一条 → **不推**，先处理再推。
2. **敏感文件靠 `.gitignore` 挡，不靠「提交后再删」**。
   一旦提交过，内容就**永久留在 git 历史里**，删文件也删不掉，只能重写历史或重建仓库。
3. **公开仓的内容从零写起**，不从私有仓复制粘贴。
4. **拿不准就不公开**。宁可少放一份文档，也不要放一份含个人信息的文档。
5. **第三方程序本体、证书、私钥、Cookie 一律不进任何仓库**（私有仓也不进）。
6. 建公开仓前先确认：**这个仓库里没有任何一行是我读到会尴尬的东西**。

## 发布前自检命令

```bash
# 1) 有没有残留密钥形态
grep -rEn "sk-[A-Za-z0-9]{16,}|ghp_[A-Za-z0-9]{20,}|AKIA[0-9A-Z]{12,}" .
# 2) 有没有协作平台标识
grep -rEn "cli_[a-z0-9]{10,}|ou_[a-z0-9]{10,}" .
# 3) 有没有绝对路径
grep -rEn "/Users/[A-Za-z0-9_.-]+/" . | head
# 4) 有没有内网/本地端口
grep -rEn "127\.0\.0\.1|192\.168\.|10\.[0-9]+\.[0-9]+\." . | head
```

> 第 4 条会在技术文档里命中大量「本地端口」说明——**端口号本身可公开**
> （如「本地代理口」），只要不带设备名、内网地址、账号信息即可。
