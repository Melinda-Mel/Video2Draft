# 11 · 跨平台重构与验收（v2）

> 目标：在**没有个人目录、没有本机服务**的新机器上，clone 仓库即可安装运行。
> 分支：`cross-platform-v2`（未合并 main）。

## 一、改了什么

| 项 | 改前（Legacy） | 改后（v2） |
|---|---|---|
| 入口 | `tools/make_card.py`（macOS 本机链路） | `tools/video2draft.py`（跨平台 CLI） |
| 抖音 / B站 / YouTube 取流 | 本机解析服务 API + Node + `mcp_call.mjs` | **仓库安装的 yt-dlp**（`python -m yt_dlp`），直接拉音频 |
| 小红书 | `xhs_reply.py`（含 `/tmp` 硬编码） | `tools/adapters/xiaohongshu.py`，纯标准库 |
| X | `x_reply.py`（含个人 yt-dlp 绝对路径） | `tools/adapters/x_twitter.py`，公开接口 + yt-dlp 兜底 |
| 视频号 | 与主链路强耦合 | **独立可选适配器** `tools/adapters/shipinhao.py`，未设 `YJCG_SPH_ENDPOINT` 即关闭 |
| 出图 | `~/.local/bin/md2pic`（外部 CLI，硬编码 Chrome 路径 + 个人 venv） | 仓库自带 `tools/md2pic.py`，用**当前解释器**调用，Chrome 跨平台探测 |
| 微信推送 | 核心程序直接调 `wx-send` | 核心程序**只出 MD / PNG / JSON**，推送交给外层 |
| 目录 | `~/WorkBuddy/<时间戳>`、`~/Documents/资料库` 写死 | `Path(__file__).resolve().parent` 推导代码目录；输出走 `YJCG_OUTPUT_DIR` |
| 临时目录 | `/tmp/...` 硬编码 | `tempfile.gettempdir()`（Windows 落到 `%TEMP%`） |
| 转写 | 依赖本机 venv + 常驻服务 | 当前解释器内 `faster-whisper`（可选 mlx） |
| 环境检查 | 无 | `install.sh` / `install.ps1` + `--doctor` |
| 自动化测试 | 无 | `tests/`（11 项）+ GitHub Actions macOS/Windows |

### 6.2 CI 暴露并修掉的真 bug（Windows 专属）

1. **子进程解码**：所有 `subprocess.run(text=True)` 都没指定 `encoding`，Windows 会用本机代码页
   （cp936/cp1252）去解子进程输出的 UTF-8 中文 → 报错或乱码。已统一改为
   `encoding="utf-8", errors="replace"`，并给子进程注入 `PYTHONIOENCODING=utf-8` / `PYTHONUTF8=1`
   （涉及 `adapters/ytdlp_platforms.py`、`adapters/x_twitter.py`、`v2d/transcribe.py`、`v2d/render.py`、`v2d/audio.py`）。
2. **控制台输出**：Windows 控制台默认 GBK，`print` 中文会 `UnicodeEncodeError`。
   `tools/video2draft.py` 与 `tools/md2pic.py` 入口统一把 stdout/stderr 重设为 UTF-8。
3. **`file://` 拼法**：`md2pic` 原先写 `"file://" + path`，在 Windows 上得到 `file://C:\...`（无效地址），
   出图会失败。改用 `Path(path).resolve().as_uri()`（→ `file:///C:/...`）。
4. **单测稳定性**：`test_missing_ffmpeg_message_is_helpful` 原先起子进程并改坏 PATH，
   在 Windows 上会影响子进程启动、`p.stdout` 变成 `None` 导致 `TypeError`。
   改为进程内打桩断言（三平台结果确定）。
5. **CI 采集方式**：部分 Windows runner 上 `subprocess.run(capture_output=True)` 会出现
   `p.stdout` / `p.stderr` 同时为 `None`，日志拿不到、还会把成功误判成失败。
   端到端脚本改为**把子进程输出重定向到文件再读**；判定与证据用 base64 annotation 回传
   （annotation 里直接塞中文/控制符会被 GitHub 解析吞掉，base64 是纯 ASCII，稳）。
