# 02 · 卡点与解决

> 这一份是整套东西里最值钱的部分：每个坑都是真金白银踩出来的。
> 按主题分组，格式统一为「现象 → 真正原因 → 处置」。

## 一、网络与代理

| 现象 | 真正原因 | 处置 |
|---|---|---|
| 某平台解析报 `reset by peer / EOF / timeout / tls` | 出网被掐：隧道没连，或 CDN 被路由到会 reset 的出口 | 报错人话化提示「稍后原样重发」；抖音类 CDN 需在代理内核里加 `DOMAIN-SUFFIX,<cdn>,DIRECT` |
| 短链直接喂解析器 → 三个适配器各重试 5 次、≈50s 才失败 | 短链域名被路由到会有问题的出口 | **先归一化**：跟随 301/302 取真实 ID，再喂完整链接 |
| 我在命令行 curl 报 000，但服务本身能成 | 命令行在沙箱里、出网受限 | **以服务侧日志为准**，别拿沙箱测试吓自己 |
| 视频号报 `please initialize the client socket connection first` | 微信客户端没连上本地 MITM 代理：代理没起，或系统代理没生效 | ① POST 服务的 `/api/proxy/restart` ② 系统代理指向 `127.0.0.1:<代理口>` ③ 微信 ⌘Q 重开 ④ 查服务 `/api/channels/status` 是否为 `available:true` |
| **VPN 一开，系统代理就「失效」** | macOS 取**主网络服务**的代理配置；VPN 连上后主服务变成 VPN 那个服务，而它当时在系统里**带 `*`（服务被禁用）**，写在它上面的代理被忽略 | 给 **Wi-Fi 和 VPN 服务两个都写**同一个代理。两个都指同一口之后，**VPN 开着关着都生效** |
| 代理起了，但服务侧连接数是 0 | 只是「代理在监听」，没有一个应用把流量送进来 | 看 `lsof -iTCP:<代理口> -sTCP:ESTABLISHED` 有没有真实应用连接；再去看系统代理是否真的被应用读到 |
| 验证系统代理是否生效 | 命令行工具会读环境变量里的代理，容易看错 | 清掉环境变量再读：`env -u http_proxy -u https_proxy python3 -c "import urllib.request as u; print(u.getproxies())"` |
| **服务一停，全机网页打不开** | 系统代理常驻指向本地口，本地口没了就断网 | 先查本地服务是否在跑；一键还原：`networksetup -setwebproxystate Wi-Fi off && networksetup -setsecurewebproxystate Wi-Fi off` |

## 二、平台适配

| 现象 | 真正原因 | 处置 |
|---|---|---|
| 小红书报 `INITIAL_STATE 中没有笔记详情` | 官方适配器读的是**旧版页面结构**，站点已改版（详情字段换了位置） | **别修适配器**，另写一个解析器抓分享页（换完整链、带 token 都没用，不是网络问题） |
| 抖音报 `mobile page has no item_list` | 用了桌面版链接 | 改用 `iesdouyin.com/share/video/<id>/` |
| 视频号老怀疑「注入脚本文件丢了」 | 注入脚本是 **go:embed 编在二进制里**的 | **不要去找 `global.js` / `hooks.js`**，不存在这回事 |
| 平台链接识别报「没认出」 | 识别表只收了主流域名，**短链域名有多个 TLD** | 把 `.com` / `.cn` 等变体都加进识别表 |
| 视频号报 `覆盖已存在任务失败: 下载任务仍在进行中` | 同一条视频的上一个下载任务还没结束，覆盖被拒 | **并非真失败**：等 10~20s 原样重跑同一条命令即可 |
| X 转出来全是莫名其妙的短句 | 视频里**没有人声**，是模型在纯音乐上的幻觉 | 先验音轨（看平均/峰值音量、有没有人声段）再判定；这条不算有效样本 |

## 三、转写

| 现象 | 真正原因 | 处置 |
|---|---|---|
| 专有名词全听错（把产品名听成音近词） | 只靠「整理阶段的白名单」**纠正不了已经听错的结果**，转写阶段也没有任何偏置 | 三层纠错：热词偏置（喂给转写器的 initial prompt）→ 转写完**确定性替换** → 整理阶段的提示兜底。词表只有一份 |
| 同一批音频，冷启动与热启动差好几秒 | 转写器每次启动都要加载模型权重 + 校验缓存 | 想快就常驻；但实测净收益只有 ≈1s，**不值得**（见 01 文档） |
| 转写末尾冒出中英俄混杂的乱句 | 视频尾部是静音/杂音，模型强解码出的幻觉 | 人工删掉那一句；将来可在收口处加「尾部幻觉守卫」（尾段混排比例过高就丢弃） |
| 拿不准某个英文词是不是听错了 | 巡检只能提醒，不能判断 | 巡检只输出「待确认英文词」清单，**不自动改**；用户确认后才进词表 |

## 四、进程与服务

| 现象 | 真正原因 | 处置 |
|---|---|---|
| `launchctl bootstrap` 连最小 plist 都报 `5: Input/output error` | 本机 launchd 域不接受新服务（沙箱内外、脚本内都一样） | **失败两次就止损**：别在这上面耗时间，常驻服务改用「用到时自愈拉起」 |
| 微信里收到两份结果：先一大段文稿、后一张图 | 机器上还跑着一个**旧的守护进程**，它监听同一条消息并自己又跑一遍，把整篇文稿分段发出去 | 停掉它并断自启（把 LaunchAgent 文件改名即可），推送只保留「一行说明 + 图」 |
| 归档目录被测试污染 | 用真实链接做端到端测试会覆盖/新增归档 | 测试前备份、测试后还原；确需删除要**先问用户** |

## 五、出图与排版

| 现象 | 真正原因 | 处置 |
|---|---|---|
| 长图里序号**全是 1** | `counter-reset` 写在了块容器里，被空行拆成多块、各自从头计数 | `counter-reset` 只能写在最外层容器，块容器只写 `counter-increment` |
| 输出图跑到当前目录、文件名是来源名 | 脚本 `main()` 里用 `src` 当局部变量，把输入路径覆盖了 | 局部变量加前缀区分 |
| 封面标题被截在句子中间、带一堆 emoji 和话题标签 | 标题直接取自平台原始标题 | 需要时对标题做清洗/截断（用户同意后再做，不要擅自改） |

## 六、协作与流程（最容易被忽略的一类）

| 现象 | 真正原因 | 处置 |
|---|---|---|
| 「你怎么又发一堆文字」 | 助理把整篇稿子贴进对话，或推送文案里附了存档路径/耗时/字数 | **只发一张图 + 一句话**；结果汇报不带过程信息 |
| 一条链接等很久，做了一堆无用功 | 收到链接先去读文档、查服务状态、解释流程，最后才开跑 | 收到链接**第一件事就是跑那条命令**，跑完再补别的 |
| 反复改文档、写总结，核心任务被挤掉 | 过程中反复维护文档 | **先实现 → 再验证 → 一次性记录**；过程中不写总结 |
| 为了「完美方案」持续试错 | 没有止损线 | **同一个问题失败两次就停**，改用现有可用方案并说明差异 |
| 等不到反馈，焦虑 | 没有进度节奏 | 3 秒内回一句「收到 + 预计多久」；超过 30 秒报当前阶段；超过 2 分钟说卡点；预计超过 5 分钟先问要不要继续 |
| 任务无限延伸 | 没有时间预算 | 普通排错 ≤3 分钟，流程改造 ≤8 分钟；超时先交付当前可用结果，把进一步优化列为可选项 |

## 七、转写与纠错的坑（2026-09-20 新增）

| 现象 | 真正原因 | 处置 |
|---|---|---|
| 稿子结尾多出几十遍同一句话，中间还夹着外语 | 视频结尾是纯音乐/卡点，转写器在上面**复读幻觉** | 两处保守拦截：连续 ≥4 段汉字部分完全相同 → 只留第一段；单段内同一句刷 ≥6 遍 → 只留一遍。**句子有一点不一样就不动** |
| 平台返回的标题里就有错字，出图后错字被放大到封面 | 只清洗了正文，没清洗标题 | 标题也要过一遍纠错表 |
| 「英文紧贴中文」时纠错不触发（`CC照长篷`） | 正则给英文变体加了 ASCII 边界 | 只有**纯英文**变体才加边界；含汉字的变体不加 |
| 中文变体加宽边界后，正常词组被误改（`上练习` → `上链习`） | 变体太短（2 字） | 删掉过短的变体；宁可漏改不可乱改 |
| 转写把产品名听成两个普通英文单词 | 光靠「别改这些词」的提示纠不回来（已经听错了） | 必须有确定性替换层，见 [04](04-术语与专有名词.md) |

## 八、推送通道的坑（2026-09-20 新增）

| 现象 | 真正原因 | 处置 |
|---|---|---|
| 推送返回 `{"ret":-2,"errmsg":"prepare failed"}` | **服务端 / 会话级**故障，不是代码问题（长轮询正常、只有发送失败） | **不要改代码**：等 1~2 分钟原样重试；实测早上挂过一次，约半小时后自愈 |
| 图片发得出去、文件（.md）发不出去 | 不同消息类型走不同 prepare 路径，文件更容易挂 | 文件失败不阻塞流程：文字 + 图先发，文件稍后补 |
| 图片、文字、文件同时全挂 | 故障扩大时的表现 | 仍按「等一会重试」处理；实在要给人看，先用本地预览 |

> 教训：推送失败**不影响产出**。产物在本地目录里，通道只是投递方式，别为了通道耗时间。
